# Как собирать и выпускать релиз

## Содержимое GitHub Releases

- `nightfall-X.Y.Z-muos.zip` — полный комплект для установки на приставку.
- `nightfall-X.Y.Z-aarch64` — бинарник для автообновления.
- `latest-aarch64.txt` — манифест апдейтера: одна строка `версия sha256 https_url`.
- `nightfall-X.Y.Z-docs.zip` — отдельный архив документации и планов.
- `INSTALL-RU.md` — инструкция, которую можно открыть или скачать отдельно.

В полном ZIP также находятся инструкция, README, дизайн, документы, игровой кадр и лицензии. Скрипты подготовки — `packaging/build-arm64.sh` и `packaging/package.sh`.

## Порядок выпуска

1. Обновить `VERSION`, журнал изменений и статус аппаратной проверки. Не выдавать запланированное за проверенное.
2. Собрать и проверить ARM64 в закреплённом Docker-образе, выполнить `make test` на Mac. Полный рецепт — в README.
3. Выполнить `NIGHTFALL_REPOSITORY=ВЛАДЕЛЕЦ/nightfall-survivors bash packaging/package.sh`. Из этого значения формируются адрес канала и адрес бинарника; после передачи владельцу Miolonixc указать `Miolonixc/nightfall-survivors`.
4. Проверить состав ZIP, соответствие `VERSION` версии бинарника и SHA-256 бинарника манифесту.
5. Сохранить изменения в Git и отправить тег `vX.Y.Z`, совпадающий с `VERSION`. Workflow GitHub Actions собирает ARM64, проверяет и публикует файлы релиза. Отдельное задание проверяет macOS; перед объявлением готовности убедиться, что оба задания успешны.
6. Дополнить описание релиза изменениями, установкой и известными ограничениями. Для новых версий предпочтителен новый тег; не изменять выпущенный бинарник под старой версией.
7. Проверить скачивание архива и манифеста. Убедиться, что манифест ссылается на уже доступный бинарник и его hash совпадает.

При ручной публикации сначала загружайте бинарник, потом манифест. Пока полного набора файлов нет, держите релиз черновиком. Пометка prerelease исключает выпуск из обычного канала `releases/latest`; не используйте её для версии, которую должен получить текущий апдейтер.

Текущая передача репозитория Miolonixc запрошена, но на момент записи ещё не принята. Фактический адрес проверяйте в GitHub; старые ссылки обычно перенаправляются после передачи. Не публикуйте токены и пароли в манифесте или ZIP.
